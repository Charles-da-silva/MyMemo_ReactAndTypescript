# Verificação de produção: autenticação e risco de deploy

**Data da verificação:** 4 de novembro de 2026
**Escopo:** inspeção dos branches remotos, do workflow do GitHub Actions, das respostas públicas do frontend e da API e dos painéis Render/Vercel. Depois da inspeção, foram cadastradas as variáveis públicas Firebase somente no ambiente Preview do Vercel, criado um deployment Preview e cadastrada a credencial privada Firebase Admin no Render. O Render reiniciou/deployou o backend; não houve merge nem alteração no Production do Vercel.

## Conclusão executiva

**O backend autenticado foi publicado em produção sem merge para `main`.** O painel do Render confirma que o serviço está ligado à branch `feature-backend-node`, com Root Directory `Backend`; após configurar a credencial Admin, o último deploy bem-sucedido e ativo é `c6ccd5b`. A implementação de autenticação foi introduzida no commit `88bd3ba`. Isso explica como suas alterações chegaram à produção sem merge.

O frontend é uma publicação independente. O domínio `mymemo.nanuvem.net` é servido pelo Vercel (confirmado pelo DNS, cabeçalhos HTTP e README); GitHub Pages é outra publicação. Os bundles públicos de produção observados ainda não aparentam conter o login Firebase; a API recusa requisições sem token (`401`). Configurei as variáveis Firebase somente em Preview, criei um deployment Preview que exibe a tela de login Google e cadastrei a credencial Firebase Admin no Render. O backend aparece `Live` em `c6ccd5b`, mas os logs mostram que as rotas autenticadas falham antes de validar o token: o código usa `admin.credential.cert`, API inexistente em `firebase-admin` 14.5.0. O usuário confirmou que conseguiu entrar no Preview, mas “Carregar Decks” falhou. A produção do Vercel não foi alterada.

## O que não foi confirmado

- Se um token Google/Firebase válido consegue autenticar-se no backend. A credencial Admin foi cadastrada, mas nenhum token foi obtido ou enviado.
- Se a migração de proprietário foi aplicada no banco de produção ou qual usuário receberia os decks antigos.
- Se os dois endereços de frontend correspondem aos mesmos processos de deploy que você usa ao testar. Os bundles vistos foram inspecionados por conteúdo, sem executar login ou alterar dados.
- Se o usuário também costuma testar o GitHub Pages; confirmou que testou `mymemo.nanuvem.net`.
- Como alinhar o branch de produção indicado pelo Vercel (`main`) com o Root Directory `Frontend`; `main` não contém essa pasta, enquanto a feature contém.

As buscas textuais nos JavaScripts de produção são um indício sobre o conteúdo dos bundles, não uma prova criptográfica da origem do build. O teste HTTP `401` sem token é direto. No Preview, o usuário confirmou login; a requisição para buscar decks falhou devido à inicialização incorreta do Firebase Admin no backend, antes da verificação do token.

## Avaliação de risco

1. **Backend autenticado confirmado em produção:** Render está ligado a `feature-backend-node` e mantém ativo o deploy `88bd3ba`. Não se deve trocar branch nem fazer merge amplo para “publicar o backend”; ele já está publicado.
2. **Autenticação com token ainda não testada no backend:** o usuário entrou no frontend, porém o backend falhou em `admin.credential.cert` antes de validar o token. A inicialização foi corrigida localmente para usar `firebase-admin/app` e `firebase-admin/auth`; ainda falta publicar e confirmar a rota autenticada.
3. **Frontend de produção ainda antigo:** os bundles públicos de produção não aparentam implementar Firebase. Foi criado um Preview que exibe login; ele não substituiu o site publicado.
4. **Validação do backend pendente:** o usuário entrou no Preview e clicou para carregar os decks. A correção local de inicialização do Firebase Admin precisa ser publicada e testada antes da promoção do frontend.
5. **Não fazer merge da branch inteira automaticamente.** A branch contém 59 commits exclusivos, incluindo a mudança de estrutura do projeto; frontend e backend usam pipelines diferentes.
6. **Frontend de produção não foi alterado.** As quatro variáveis foram cadastradas exclusivamente para Preview e foi criado um deployment Preview. O backend Render recebeu a credencial Admin e foi reiniciado; o usuário confirmou o login no Preview, mas o middleware do backend falhou.
